# Immutable generation namespaces

`tools/singapore-full/namespace/index.mjs` is a dependency-free Node ESM module and CLI. It separates run identity from the queue scheduler. No Minecraft or generator is launched by this module.

A run is identified by SHA256 of a canonical descriptor. Object keys use binary lexical sorting, arrays retain order, hashes normalize to lowercase, and only finite JSON values are accepted. Absolute paths, machine names, timestamps, worker IDs and attempt numbers are absent from the descriptor. The complete 64-character digest is the run ID; it is not truncated.

## Descriptor

```json
{
  "schema": 1,
  "inputs": {
    "source_sha256": "<accepted frozen source SHA256>",
    "mask_sha256": "<accepted frozen mask SHA256>",
    "ancillary_sha256": {
      "palette": "<palette snapshot SHA256>",
      "terrain": "<terrain snapshot or explicit absent-policy SHA256>",
      "vertical_policy": "<provisional vertical-policy SHA256>"
    }
  },
  "generator": {
    "code_sha256": "<complete generator code-set SHA256>",
    "config_sha256": "<canonical semantic configuration SHA256>"
  },
  "spatial": {
    "projection_sha256": "<projection and grid-origin policy SHA256>",
    "datum_sha256": "<vertical datum and conversion policy SHA256>"
  }
}
```

Every placeholder is exactly 64 hexadecimal characters in actual input. The caller fingerprints accepted content, not a mutable filename. `fingerprintFile(path)` streams actual file bytes and rejects a file that changes during hashing. `fingerprintJson(value)` canonicalizes semantic JSON. For a code set or multi-file dataset, fingerprint a logical-name-to-file-SHA256 map. Include the renderer, invocation adapter, dependent voxel/geometry helpers and their semantic policy/configuration. An Arnis binary hash alone is insufficient when a different renderer writes the world.

Ancillary logical names must be portable labels, not paths. Fingerprint explicit JSON describing an absent source or provisional policy when a dataset is unavailable; do not invent a dataset checksum or omit a material policy. Include code/config changes that alter geometry, palette, feature selection, masking, projection, elevation or datum conversion. Exclude output/cache directories, host executables and operational scheduling limits from the semantic configuration fingerprint. Pin actual executable/library versions in the code-set identity when they can change generated bytes.

This is an identity/cache gate, not evidence that source data, terrain, facades or building heights are accurate. Those acceptance gates remain separate.

## Queue adapter contract

```js
import { ensureRun, queueFingerprints } from './namespace/index.mjs';

const run = ensureRun(privateRunsRoot, descriptor);
const queueRoot = `${run.run_dir}/queue`;
const fingerprints = queueFingerprints(descriptor);
// Queue spec: { ...fingerprints, argv, cwd, dependencies, ...limits }
// argv retains literal {output_dir}, {checkpoint}, {job_id} placeholders.
```

The queue owns its job IDs, retries, output promotion, checkpoint and attempt folders beneath `queueRoot`. Do not call `createAttempt` inside a queue attempt. The adapter must pass the queue's exact `output_dir` to the generator and must not retain a fixed tile-ID output directory or a shared root-level generator lock.

`queueFingerprints` returns the queue's `sourceSha256`, `codeSha256`, `configSha256` fields. Its configuration digest also binds the mask, all ancillary hashes, projection and datum. Thus an accidentally relocated queue still cannot reuse results from a different mask or elevation policy. Existing queue specs may include paths in their own job hash; that creates safe cache misses across machines, while the outer generation run ID remains portable.

Call `ensureRun` once in the coordinator before queue workers start. It creates `run-<full SHA256>/run.json` and `attempts/`. Reopening the same descriptor returns the same directory without rewriting metadata. A foreign/incomplete run directory or a conflicting manifest is rejected; preserve it for diagnosis and use a separate namespace root for recovery. The filesystem must support hard links for atomic exclusive manifest installation (Desktop NTFS does).

## Standalone attempts and verified copies

These APIs are an optional non-queue fallback:

```js
const attempt = createAttempt(root, runId, 'tile-001', { depends_on: ['source', 'mask'] });
// Returns run_id, attempt_id, job_id, depends_on, run_dir, attempt_dir,
// output_dir, checkpoint. Start the generator using these exact paths.
// Stop and wait for the output writer before committing.
const complete = commitAttempt(root, runId, attempt.attempt_id);
const checked = verifyAttempt(root, runId, attempt.attempt_id);
const copied = cloneAttempt(root, runId, attempt.attempt_id);
```

Each attempt gets a fresh UUID, output directory and checkpoint path. An interrupted attempt is never treated as complete and is never overwritten. Dependency IDs are recorded; dependency readiness belongs to the scheduler. `complete.json` inventories every regular output file's relative path, byte length and SHA256. Recommit is idempotent only while bytes remain identical. Modified, missing, additional or non-regular output entries reject reuse. Empty directories are not part of the content identity. Symlinks/junctions and case/Unicode path collisions are rejected.

`cloneAttempt` requires a verified committed source in the same run and same logical job, copies files exclusively into a fresh attempt, rehashes the copied inventory and commits it. It does not use hard links for generated output. Partial/failed copies remain uncommitted and never replace prior output. A changed source/code/config/mask/datum must create a new run and regenerate; cross-run cloning is intentionally unsupported.

Manifest writes install a fully flushed temporary file with an exclusive hard link. They never overwrite a conflicting destination. This protects against concurrent manifest writers, but does not freeze a generator that continues modifying output. The caller must wait for its writer to exit before commit and reverify immediately before accepting cached output.

## CLI

```text
node index.mjs id descriptor.json
node index.mjs init ROOT descriptor.json
node index.mjs attempt ROOT RUN_ID JOB_ID [dependencies.json]
node index.mjs commit ROOT RUN_ID ATTEMPT_ID
node index.mjs verify ROOT RUN_ID ATTEMPT_ID
node index.mjs clone ROOT RUN_ID ATTEMPT_ID
node index.mjs hash-file FILE
node index.mjs hash-json FILE
```

Success writes one JSON value to stdout. Failure writes `{ "error": "..." }` to stderr and exits 1. Descriptor files may contain a UTF-8 BOM. `dependencies.json` is an array of logical job IDs.

Focused checks on Desktop:

```text
node --check tools/singapore-full/namespace/index.mjs
node --test tools/singapore-full/namespace/namespace.test.mjs
```

The tests use tiny temporary fixtures. They verify canonical order, all material fingerprint changes, invalid identities, immutable run collisions, independent attempts, real separate-process restart, modified/missing/extra output rejection, exclusive verified cloning, interrupted attempts and junction rejection. No large map generation or current game/profile changes are performed.
